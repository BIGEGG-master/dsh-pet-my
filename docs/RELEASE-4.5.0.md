# v4.5.0 更新日志（2026-11-12）

> 4.4.1 → 4.5.0。这一版是「她能自己记住东西」：**记忆卡**（深层记忆的可视面 +
> 照片附件 + 她写的感受）与**嘟嘟的日记**，外加角色卡的两种文件格式与人设两段式。
>
> 版本号按语义化取 **minor**（4.5.0）：功能新增，不改记忆/会话的存储格式。

## 设计红线：记忆卡不是第二套记忆

**底层完全是原来的记忆模块**（`pet/chat/memory.py`）：条目、层
（`user/fact/lesson/topic`）、`hits`、归档、限额、注入逻辑一个字都没改。

记忆卡（`pet/memory_card.py`）只是它的**视图**：

| 面板上看到 | 来自 |
| --- | --- |
| 一条条记忆 | `sessions/<角色>/memory.json` 里的条目（`ChatMemory.load()`） |
| 偏好 / 事实 / 教训 / 话题 | 条目自己的 `layer` |
| 「命中 N 次」 | 条目自己的 `hits` |
| 「她的感受」 | 条目自己的 `feeling`（提炼时她一起写的） |
| 照片 | 条目的 `photo` 字段 + 同目录 `memory-photos/<条目 id>.<后缀>` |
| 删掉一条 | `ChatMemory.remove(条目 id)` ——记忆文件真的少一条 |

没有自己的索引、没有第二条写入路径、没有额外的"同步"步骤。

## 新增

### 1. 右键「查看记忆卡」

- **谁决定记住什么**：她自己。每轮对话后的自动提炼分析值不值得记、要不要改旧条目，
  输出的 ADD / UPDATE / FORGET 直接落 `memory.json`；面板把结果摊开给你看。
- **每条记忆带一句「她的感受」**：提炼时同一次请求里她用第一人称写（
  `entry.feeling`，≤120 字），面板上显示在正文下面。
  - 感受**不进注入**（不占对话预算），只给她自己/给你回看；
  - 没有感受的条目就不写这个字段；重申同一条记忆时带了新感受才会覆盖。
- **照片也一样**：发图时先把图复制进 `memory-photos/pending/`（粘贴图发送后会
  被系统清理），回复完成后她判断这张图值不值得记（`pet/chat/photo_memory.py`）：
  - 值得 → ADD 一条 `layer=topic` 的记忆（正文是她的备注，如「哥哥画的鲸鱼」），
    并写一句感受；图挪进 `memory-photos/<条目 id>.png` 挂在这条记忆上；
  - 不值得（随手截图 / 表情包 / 测试图）→ 删掉暂存副本，记忆里什么都不留；
  - 判断请求失败 → 保守保留（图是你明确发来的），备注用你当时那句话。
- 面板：搜正文、按层筛选、双击看全文或大图、删一条（等于让她忘掉，二次确认）。
- **没有「手动写一条」**：记忆由她的判断产生。

### 2. 右键「嘟嘟的日记」

- 把 `sessions/<角色>/*.json` 的真实对话按天编成日记：当天几次、起止时间、
  按时间引用几句原话、一共几句。
- 只写发生过的事；语气是她的（每段最多一个「嘟」）。
- 左侧按天列、右侧正文；顶部搜索跨全部天数；范围可选全部 / 近 7 / 30 / 90 天；
  「导出这一天」写成 txt（UTF-8 BOM）。
- 只读会话文件，不产生第二份数据。

### 3. 角色卡：JSON 与 Markdown 都能读，人设支持两段式

**两种输入格式**（设置 → AI → 角色卡 →「从文件导入…」）：

- `persona-card/v1` **JSON**：人设 + 显示名 + 全部事件台词（可带台词）；
- **Markdown / TXT**：`# 标题` 当显示名（自动去掉「角色卡：」这类前缀），
  其余正文整段当人设；没有台词，应用时**不动**现有台词。

导入统一落成 `persona-cards/<id>.json`；md 的 id 由正文哈希决定，同内容重复导入
只刷新那一张。`.json` 后缀但内容是 Markdown 的文件也尽量按 md 读。

**人设不再二选一**（`compose_prompt`）：

| 配置键 | 含义 |
| --- | --- |
| `prompt_base` | 主体人设（来自角色卡，或你自己写的） |
| `prompt_supplement` | 你手写的补充说明（追加在主体之后） |
| `prompt_merge` | 开关：开 = 两段叠加；关 = 只用主体（补充保留在配置里） |
| `default_system_prompt` | 运行时唯一读取的合成结果（合成逻辑只在保存/应用卡时跑） |

- 应用角色卡**只换主体**，你的补充说明保留并继续叠加——不再被卡覆盖；
- 设置页有独立的「补充说明」输入框与「角色卡 + 补充同时生效」开关；
- `prompt_source` 记录主体来源（`card:<id>` / `manual`），设置页据此说明归属；
- 老配置只有 `default_system_prompt` 时，打开设置页会把它当主体显示，行为不变。

## 变更

- 默认右键菜单在「AI 对话」下新增「查看记忆卡」「嘟嘟的日记」；老用户的自定义
  布局会自动并入这两项（按模板相邻位置插入），不想要可在菜单编辑器取消勾选。
- 两项归在 `chat` 功能模块下：停用「AI 对话」时一起消失。
- 内置「嘟嘟」角色卡（`pet/persona_cards/builtin/dudu.json`，30 组台词）。

## 升级说明

- **不动旧数据**：记忆、会话、配置格式不变；`prompt_base` / `prompt_supplement` /
  `prompt_merge` 都是新增键，缺省按"主体 = 现有 System Prompt、补充为空、叠加开"处理。
- 第一次打开记忆卡看到的就是已有记忆条目（层、命中次数都在），没有感受的条目
  只是不显示那一行；之后新提炼/新照片才会有感受。
- 照片记忆需要当前 provider 支持图片输入；不支持时按保守策略保留。

## 已知限制

- 日记正文是**本地拼装**的（读原文 + 时间），不花钱、不联网、不会编造。
- 记忆卡跨角色聚合显示；记忆本身仍按角色隔离。
- 照片判断一次最多处理这一轮的前 4 张图（成本护栏）。
- 「她的感受」不进注入：这是刻意的取舍（注入预算 1200 字，且它不是给模型的事实）。
