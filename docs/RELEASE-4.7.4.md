## 一、过渡段从哪来

用户提供的 4 段素材里，两段的方向其实是**「躺 → 坐起」**（用逐帧包围盒量出来的，
不是猜的）：

| 片段 | 首帧 | 末帧 | 方向 |
| --- | --- | --- | --- |
| `4d27…` | 760×328（宽而矮=躺） | 618×565（窄而高=坐起） | 躺 → 坐起 |
| `34ea…` | 550×385 | 454×504 | 躺 → 坐起（幅度更小） |

取 `4d27`（幅度最大、首帧与常驻躺姿 `睡觉-主` 的 740×347 几乎重合），裁出变化区间
（`motion_window` 找高度开始/结束变化，两端各留 6 帧静止，再中心裁到 3.2s / 77 帧），
双向各编一段：

| 素材 | 构成 | 用途 |
| --- | --- | --- |
| `入睡过渡.webm` | **倒放**（坐起 → 躺下） | 点「去睡觉」时播一遍，落点正好是躺姿 |
| `醒来过渡.webm` | **正放**（躺 → 坐起） | 醒来时播一遍，落点在坐姿 |

几何对齐：整段统一缩放（按中位宽度），并让**结束帧**的底部落在画布 92%、中心 50%
——衔接发生在结尾，所以对齐结尾。

## 二、接线（不加定时器）

```
入睡：sleep_changed(True)
  → switch_clip("入睡过渡")        # 一次性 ACTS
  → 播完 _roll_next 命中 hold 闸门 → 自动进「睡觉-主」常驻
醒来：sleep_changed(False)
  → release_hold()                # 摘掉常驻
  → switch_clip("醒来过渡")         # 一次性
  → 播完正常掷骰回待机
```

为什么不用定时器：hold 判据在 `sleeping=True` 的那一刻就已经返回 `睡觉-主`，
过渡段作为普通 ACTS 播完之后，`_roll_next` 的闸门本来就会把它接回常驻姿态。
醒来同理——先摘常驻再播起身段，播完自然回到掷骰链。

新增关键词池：

```python
"sleep_in":  ("入睡过渡",)
"sleep_out": ("醒来过渡",)
```

过渡段缺素材时**自动退回旧行为**（直接切睡姿 / 只摘常驻），不会卡住。
淡入（0.35s）保留：进入过渡段的瞬间也不会硬切。
