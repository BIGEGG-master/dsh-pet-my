## 1. DSH 端口自动发现

**问题**：`pet/agent_link/dsh_state.py :: candidate_ports()` 只认 `{3080, 38080, 19387}` + `DSH_PORT`。
DSH 实际端口是启动时分配的（本机 27084 / 9230 / 12454），不注入就永远 `offline`。

**改法**（两处，都很小）：

1. `pet/harness_launcher.py` 新增：
   ```python
   _DISCOVER_TTL = 20.0
   _discover_cache: tuple[float, list[int]] = (0.0, [])

   def discover_dsh_ports() -> list[int]:
       """动态发现 DSH 实际监听的端口（桥文件 pid 优先，其次桌面端进程）。"""
   ```
   - 首选：`%APPDATA%/dsh-pet-bridge/dsh-{pid}.jsonl` 里的 pid → `psutil.Process(pid).net_connections()`
   - 兜底：进程名 `DeepSeek Harness.exe` 的监听端口
   - 缓存 20s、去重、最多 8 个，失败返回 `[]`

2. `pet/agent_link/__init__.py :: DshMonitor._probe_online()`
   ```python
   ports = list(_dsh_state_candidate_ports())
   ports += harness_launcher.discover_dsh_ports()
   online = any(harness_launcher.is_running(p) for p in ports)
   ```

**验收**：不设 `DSH_PORT` 启动桌宠，日志应出现 `[DSH STATE] idle -> working`。

## 2. DSH 对话记忆原生进桌宠记忆

**新增** `pet/chat/dsh_memory.py`：

```python
def import_into(memory: ChatMemory, *, force: bool = False) -> int:
    """把 ~/.dsh/dsh-pet/memory.json 的真人消息转成记忆条目，返回新增条数。"""
```

- 读 `~/.dsh/dsh-pet/memory.json`（`{桶: {宠物: {messages: [...]}}}`）
- 只取 `role == "user"`，分类规则与 `_internal/integrations/dsh-pet-memory-bridge/memory_bridge.py`
  一致（fact / lesson / topic；寒暄与纯数字跳过）
- 通过 `ChatMemory.apply_ops(ops, source="auto")` **一次**落盘（自带跨进程锁与去重）
- 模块级节流 60s；读失败只记日志、不写盘

**接入点**：`pet/chat/memory.py :: memory_payload()` 顶部调一次（每轮对话前同步，
这样"这一轮就能用上"），以及 `pet/chat/memory_extract.py` 的提炼之后。

**配置**：新增 `chat_memory_dsh_sync`（默认 True）+ `chat_memory_dsh_sync_seconds`（默认 60）。

**验收**：往插件 `memory.json` 追加「我喜欢吃辣」，桌宠聊一句后 `记忆管理` 里出现该条目（`origin` 可追溯）。

## 4. 随 DSH 启停（桌宠侧）

**问题**：现在靠外部 DSH 插件（`D:\DSH-Plugins\dsh-pet-lifecycle`）拉起/关闭，
桌宠自己不知道 DSH 在不在。

**改法**：`pet/app.py :: AppShell`

- 新增 `_DshQuitFollower`：订阅 `AgentLinkManager.dsh_state_changed`
  - `to == "offline"` 且**曾经在线过** → 启动 `QTimer`（`dsh_quit_grace_seconds`，默认 20s）
  - 期间任何非 offline 状态 → 停表
  - 超时 → 走 `_on_about_to_quit` 正常退出路径
- 配置：`dsh_quit_with_dsh`（默认 True）、`dsh_quit_grace_seconds`（默认 20）
- 「随 DSH 启动」仍由 DSH 插件负责（桌宠无法自己从 0 启动，除非 DSH 拉起它）

**验收**：开着 DSH 启动桌宠 → 退出 DSH → 约 20s 后桌宠退出；重启 DSH → 插件拉起桌宠。
