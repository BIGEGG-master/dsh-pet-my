# 4.4.1 增强说明（DSH ⇄ 桌宠）

这份仓库在官方 **4.4.0** 源码基础上加了四项与 DSH 的联动能力，并配了一套可版本化迭代的
开发脚本（`dev\`）。以下内容与具体机器路径无关，拿到包的人按 `dev\README.md` 操作即可。

## 一、四项原生功能（都改在 `pet/` 里，不是外挂）

### 1. DSH 端口自动发现

**问题**：`DshMonitor` 判 DSH 是否在线时只认 `{3080, 19387, 38080}` + `DSH_PORT` 环境变量，
而 DSH 的实际端口是启动时分配的（实测 27084/9230/12454），于是「用户自己开的 DSH」永远 offline。

**改法**：
- `pet/harness_launcher.py :: discover_dsh_ports()` —— 从桥文件 `dsh-pet-bridge/dsh-{pid}.jsonl`
  取写者 pid，用 psutil 查该进程的 LISTEN 端口（20 秒缓存，失败退回桌面端进程名匹配）；
- `pet/agent_link/__init__.py :: DshMonitor._probe_online()` —— 在静态候选之后叠加动态端口。

**验证**：不设 `DSH_PORT` 直接启动，日志应出现 `[DSH STATE] idle -> working`。

### 2. DSH 对话记忆原生同步

新增 `pet/chat/dsh_memory.py`：每次发问（`ChatWindow._memory_injection`）前，以 60 秒节流读
`~/.dsh/dsh-pet/memory.json`（插件版记忆），把**真人消息**分类成 `fact / lesson / topic`，
通过 `ChatMemory.apply_ops` 一次性并进本机记忆文件。

- 只取 `role == "user"`；寒暄、纯数字、过短不导入；
- 已存在的文本不再 ADD（否则每 60 秒会把 hits 刷一遍、搅乱 topic 的 14 天归档）；
- 读失败只记日志，一个字节都不写；
- `tests/test_dsh_memory.py` 覆盖分类、解析、幂等、节流。

`integrations/dsh-pet-memory-bridge/` 是同一件事的**独立脚本版**（不重新打包也能用），
额外提供反向导出：把桌宠记忆写成 `~/.dsh/dsh-pet/memory-bridge/memory.{json,md}`。

### 3. 角色卡（设置项）

新增 `pet/persona_cards.py` + `pet/persona_cards/builtin/feiyu.json`（内置「小肥鱼」，30 组台词），
在 **设置 → AI → 角色卡** 里可切换：

| 卡里的字段 | 写入配置 |
| --- | --- |
| `system_prompt` | `chat.default_system_prompt` |
| `aliases` | `character_aliases`（改角色显示名） |
| `phrases` | `dialogue_mode = custom` + `dialogue_phrases` |

支持从 JSON 导入 / 导出（同 id 覆盖），用户卡落在 `<配置目录>/persona-cards/`。
`tests/test_persona_cards.py` 覆盖加载、应用、模板转换、用户卡覆盖。

### 4. 随 DSH 启停

- **启动**：`integrations` 之外还有一个 DSH 侧插件 `dsh-pet-lifecycle`（本仓库不含，见下方"配套插件"）：
  DSH 起来后延迟 3 秒拉起桌宠（没运行就启动、在跑就接管）并注入 `DSH_PORT`。
- **关闭**：`pet/app.py :: _follow_dsh_lifecycle` —— 订阅收敛状态，`offline` 且**曾经在线过**
  才倒计时（默认 20 秒，`dsh_quit_grace_seconds` 可调），期间恢复即取消。桌宠单独使用时永不自退。
  `tests/test_dsh_quit_follow.py` 覆盖全部分支。

## 二、配套的 DSH 侧插件

`dsh-pet-lifecycle`（让 DSH 拉起/关闭桌宠）不在本仓库里，它是独立的 DSH bundle 插件，结构：

```
package.json      # dsh.bundle.patch -> cordis.patch.yml
cordis.patch.yml  # - insert: [{id: dsh-pet-lifecycle, name: dsh-pet-lifecycle}]
index.js          # apply(ctx): 延迟探测并拉起 exe；ctx.effect 里登记退出收口
```

安装方式：在 DSH profile 的 `package.json` 里加 `"dsh-pet-lifecycle": "link:<插件目录>"`，
并把 `dsh-pet-lifecycle` 加进 `dsh.profile.bundles`，再在 `node_modules` 建 junction。

## 三、开发脚本（`dev\`）

```powershell
powershell -File dev\setup.ps1                            # 建 .venv 装依赖
powershell -File dev\run.ps1                              # 源码直跑
powershell -File dev\build.ps1 -Bump patch -SkipZip       # 升版本 + 打包
powershell -File dev\publish.ps1 -Target <安装目录>        # 部署并启动
powershell -File dev\pack_source.ps1                      # 打可分发的源码 zip
.venv\Scripts\python.exe dev\configure_ai.py --key sk-xxx --test
```

两个必读的坑：

1. `assets/characters/<角色>/frameseq/` 是 `.gitignore` 的派生产物，仓库里没有 → 构建门会拦。
   要么先跑 `python tools/convert_frameseq.py --character shenshen --include random,events`
   补齐（实测 1 clip/分钟），要么 `dev\build.ps1 -SkipCheck`（运行时按启动预算补转，
   与官方安装包现状一致）。
2. `dev\*.ps1` 与 `scripts\build_onedir.ps1` **必须带 UTF-8 BOM**，否则 PowerShell 5.1
   按 GBK 解析中文注释会直接语法报错。

## 四、数据目录

| 运行方式 | 数据目录 |
| --- | --- |
| 打包变体（`dsh-pet-standalone-webm-chat.exe`） | `%APPDATA%\dsh-pet-standalone-webm-chat\` |
| 源码直跑（`dev\run.ps1`） | `%APPDATA%\dsh-pet-standalone\` |

源码里没有 `packaging/build_variant.py` 时，`_app_dir_name()` 会回退到共享名。两边**各有一份**
配置与记忆，「源码模式改了看不到」不是 bug。

## 五、已知限制

- 构建版默认不含完整 frameseq（见上），首启时动画会先走 webm 直出。
- 桌宠的「关闭」是隐藏到托盘，DSH 插件侧的优雅关窗多半无效、最终强杀（不保存窗口位置）。
- `_follow_dsh_lifecycle` 只认「在线过之后的离线」：DSH 从未出现时桌宠不会自退。
- AI 对话的 key 存在系统钥匙串（service `dsh-pet-standalone`），config.json 里只有 ref；
  换机器/换用户需要重新跑 `dev\configure_ai.py`。
